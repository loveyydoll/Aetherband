## How to maintain this file

- Add entries under **Unreleased** as meaningful changes are made.
- Group entries under **Added**, **Changed**, **Fixed**, **Removed**, or **Known limitations** when that improves clarity.
- When publishing a release, move the relevant entries into a versioned section with the actual publication date.
- Do not treat a merged pull request as a release, invent release dates, or list planned features as implemented.
- Keep routine implementation detail in commit messages and pull requests; use this file for changes people should know about.
